# 49-slice agent split — 31 October 2026

Forty-nine slices, seven waves of seven. The number is the *work split*, not the
number of agents: `spawn_agents` caps at six per call, and more importantly
`ORCA/OWNERSHIP.md` records that two writers in one file merge with no conflict
marker at all and break the build — `silhouette.gd` shipped exactly that way.
Parallelism here comes from **file ownership**, so the rule is:

> No two slices in the same wave share a file. Ever.

`bone_yard_hunt.gd` (11.6k lines) appears in **one slice per wave, at most**.
Everything else is a single-owner file or a single-owner test.

Each slice ships one change plus the suite that guards it. Exit code is the
authority, and a suite that prints nothing has not passed (`ORCA/RULES.md` 2).

```bash
cd P:/GameDev/AllusionsTooGrandeur && bash tools/run_tests.sh <suite>
```

Waves run in order. A wave finishes when all seven suites are green on the same
tree; then the tree is committed by explicit path and the next wave starts.
Between waves, run `bash tools/run_tests.sh --core`.

## Why not 49 agents at once

Two reasons, both measured in this repo.

**File ownership.** Waves exist because ownership is per-file. Fifty agents on
one Godot tree means collisions git will not report: the merge succeeds, the
build does not. That is not a hypothetical — it is the founding incident in
`ORCA/OWNERSHIP.md`.

**Verification is the bottleneck, not generation.** Every slice above needs its
suite run on a clean tree, and `holding_work_integration_test` alone takes about
18 seconds. Six agents each writing code they cannot independently verify
produces six untested diffs; the cost of checking them afterwards is higher than
writing them in order.

**Good parallel points:** wave-internal slices (disjoint files), and the `--all`
suite sweep while code is being written in a *separate worktree*.

**Bad parallel points:** anything touching `bone_yard_hunt.gd`, `world_index.gd`
or `gothic_field_hud.gd` concurrently; any two agents in the same worktree; and
two agents both running `--import` at once.
